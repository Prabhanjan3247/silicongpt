# SiliconGPT — End-to-end demonstration (8-bit ALU)

Everything in this walkthrough is produced by real tools on real files: Icarus Verilog / Verilator
simulations, Yosys synthesis and the VCD written by the simulator. Numbers below are the values
observed on the development host; your timings will differ.

Prerequisites: backend on `http://127.0.0.1:8000`, UI on `http://127.0.0.1:5173` (see README →
Running). AI steps need `ANTHROPIC_API_KEY` in `backend/.env`; without it they show the backend's
"Claude API credentials not configured" error and every other step still works.

## 1. Open the example ALU project
**Dashboard → "Open the 8-bit ALU demo"** (or **Projects → Examples → 8-bit ALU → Open**). A fresh copy
of `examples/alu8` is created and opened in **RTL Editor** with `alu8.v` (RTL) and `tb_alu8.v`
(testbench). The ALU supports ADD, SUB, AND, OR, XOR, NOT, flags `carry/zero/negative/overflow` and
flags reserved opcodes as `invalid`.

## 2. Explain the RTL with AI
Right panel **Explain → Overview / Line by line**. The RTL Developer agent returns the module purpose,
interface table and line-range explanations; clicking a block highlights those lines in the editor.

## 3. Generate (or inspect) the testbench
**Verification → Generate testbench** asks the Verification Engineer agent for a self-checking
`[SGPT]` testbench for `alu8`, compiles it with the selected simulator and shows the test plan,
coverage bins and compile result; **Save to project** stores it. The example already ships with a
hand-verified testbench (`tb_alu8.v`: directed, boundary, corner, invalid-opcode and 256 random vectors
against an integer reference model; 26 coverage bins), which the rest of the demo uses.

## 4. Compile the RTL
**RTL Editor → Compile** (Icarus) — real compiler output in the *Compilation Log* tab; **Lint** adds
Verilator `-Wall` + Icarus diagnostics as editor markers (0 for this design).

## 5. Run the simulation
**Run Simulation** → *Test Results*: **774 / 774 checks passed**, verdict `passed`, TB-reported functional
coverage 26/26 bins (100 %), compile ≈0.35 s, simulation ≈0.15 s. Switch the simulator to **Verilator**
to cross-check (≈15–20 s build, same 774/774).

## 6. Inspect waveform signals
**Waveforms** (or the *last run* link) shows the VCD of that run: `a`, `b`, `op`, `y` and the flags. Click
to place the cursor and read every value at that time; shift-click for a delta marker; ctrl+wheel to
zoom; switch bus radix hex/dec/bin; **Download VCD** opens in GTKWave.

## 7. Introduce a deliberate bug
**RTL Editor → fault-injection menu → "SUB drops the +1 carry-in"**. The real file is edited
(`{carry, y} = {1'b0, a} + {1'b0, ~b} + 9'd1;` → `... + {1'b0, ~b};`) and the previous content is kept as
a `fault_injection` revision.

## 8. Run the testbench again
**Run Simulation** → verdict `failed`: **127 of 774 checks fail** — all SUB vectors.

## 9. Show the failing test case
*Test Results* (filter FAIL), e.g.
`directed_SUB_8  time=85000  exp=0x010f  act=0x010e  :: op=SUB a=0x10 b=0x01 mismatch: y exp=0x0f act=0x0e`.
The **Verification** page shows the same run with pass/fail charts, checks by category and history.

## 10. Ask the AI debugger
**Debugger** (picks the latest failing run) → **Diagnose with AI**. The Debugging Engineer receives the
failing records, logs, VCD values of the DUT signals at the failure times and the numbered RTL, and
returns the failing operation (SUB), the control signal (`op = 3'b001`), expected vs actual, suspected
file/lines, root cause and a confidence level, plus a patch. The backend immediately re-simulates the
patched snapshot (*pre-validation run*) and shows its verdict next to the diff.

## 11. Apply the proposed patch
**Apply patch** writes the patched file (kept as an `ai_patch` revision, so it is traceable and
revertible).

## 12. Re-run the simulation
**Re-run simulation** → **774 / 774 passed** again.

## 13. Show the verified result and report
**Reports → current project**: verification statement (e.g. "Run #3 (icarus) PASSED 774/774 checks;
TB-reported functional coverage 26/26 bins"), run history including the failing run, the debug session
and the applied patch, synthesis numbers (**Optimize → Run baseline synthesis**: 190 cells, 0 flip-flops,
0 latches, logic depth 18) and the limitations. Download as Markdown or HTML.

## Without an API key
Steps 2, 3 (generation), and 10 need Claude. Without credentials, run the rest and restore the RTL in
step 10 from **RTL Editor → file history → revert the `fault_injection` revision** — a manual fix,
recorded as such. `scripts/demo_e2e.py` automates exactly this fallback and prints every real result:

```bash
backend/.venv/Scripts/python.exe scripts/demo_e2e.py --verilator
```
